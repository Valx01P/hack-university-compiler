# Creating Tables

`CREATE TABLE` names the table and lists its columns, each with a type and optional default and constraints. Give every table an identity primary key, so Postgres numbers the rows for you.

### Create

```sql
CREATE TABLE users (
    id         integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name       text NOT NULL,
    email      text UNIQUE,
    age        integer,
    is_admin   boolean NOT NULL DEFAULT false,
    created_at timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE IF NOT EXISTS users (id integer);  -- NOTICE, no error, keeps the old table
```

### Identity columns

```sql
CREATE TABLE tags (
    id   bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name text NOT NULL
);

INSERT INTO tags (name) VALUES ('sql');            -- id 1
INSERT INTO tags (id, name) VALUES (100, 'pg');    -- BY DEFAULT lets you pick
INSERT INTO users (name) VALUES ('Ana');           -- id 1, is_admin f
```

| Spelling | Means |
| --- | --- |
| `GENERATED ALWAYS AS IDENTITY` | Postgres always picks the id, an explicit id is an error |
| `GENERATED BY DEFAULT AS IDENTITY` | picks one unless you give one |
| `serial` / `bigserial` | the older way, an `integer` with a sequence default |

### Column types people use

```sql
CREATE TABLE items (
    id         integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    sku        varchar(20) NOT NULL,
    name       text NOT NULL,
    price      numeric(10, 2) NOT NULL DEFAULT 0,
    weight_kg  real,
    stock      integer NOT NULL DEFAULT 0,
    in_stock   boolean GENERATED ALWAYS AS (stock > 0) STORED,
    released   date,
    tags       text[] NOT NULL DEFAULT '{}',
    attrs      jsonb NOT NULL DEFAULT '{}',
    code       uuid DEFAULT gen_random_uuid()
);
```

| Type | Holds |
| --- | --- |
| `integer`, `bigint`, `smallint` | whole numbers (4, 8, 2 bytes) |
| `numeric(p, s)` | exact decimals, use for money |
| `real`, `double precision` | floating point |
| `text`, `varchar(n)` | strings, `varchar(n)` errors past `n` chars |
| `boolean` | `true`, `false`, or `NULL` |
| `date`, `time`, `timestamp`, `timestamptz` | dates and times |
| `interval` | a span like `'2 days'` |
| `uuid`, `jsonb`, `text[]` | ids, JSON, arrays |

### Copy a table

```sql
CREATE TABLE users_backup AS SELECT * FROM users;             -- data, no constraints
CREATE TABLE users_empty (LIKE users INCLUDING ALL);          -- structure, no rows
CREATE TEMP TABLE scratch (n integer);                        -- gone when the session ends
```

### Look at a table

```sql
SELECT column_name, data_type, column_default IS NOT NULL AS has_default
FROM information_schema.columns
WHERE table_name = 'users'
ORDER BY ordinal_position;
-- id         | integer                  | f
-- name       | text                     | f
-- email      | text                     | f
-- age        | integer                  | f
-- is_admin   | boolean                  | t
-- created_at | timestamp with time zone | t
```

`\d users` works in `psql`, but it is a `psql` command, not SQL, so it does not run here.

### Gotchas

- Unquoted names fold to lowercase. `CREATE TABLE "Users"` makes a name you must quote forever, so stick to `snake_case`.
- `user`, `order`, and `group` are reserved words. Name tables `users`, `orders`, `groups`.
- Use `numeric` for money. `real` and `double precision` round: `0.1::float8 + 0.2 = 0.3` is `f` (see Math).
- Prefer `timestamptz` over `timestamp`. It stores an absolute moment and converts to the session time zone.
