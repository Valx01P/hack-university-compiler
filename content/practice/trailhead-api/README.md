# Trailhead API

The course's backend: a small Node.js server with no dependencies. Start it from your Playground folder with `node trailhead-api/server.mjs` (or `node server.mjs` from inside this folder), and it answers at `http://127.0.0.1:4000/v1`, with the twelve products of the catalog, and two accounts, `sam@example.com` and `ana@example.com`, whose password is `trailhead`. Everything lives in memory, so stopping the server throws your changes away and the next start begins from the same seed data, `openapi.yaml` next to it describes every operation, and `images/` holds the twelve product photos the API's `imageUrl` paths name: copy that folder into your shop's `public` folder (`cp -r trailhead-api/images trailhead/public/`), since the browser asks the shop for them.

Settings, all optional: `PORT` picks another port, `HU_FIXED_TIME` sets the time the seed data treats as now (`2026-10-01T09:00:00Z` by default), `TRAILHEAD_DELAYS=1` slows answers down like a real network (products 300 ms, a product 200 ms, reviews 900 ms, `/me` 150 ms, the cart 400 ms), and `TRAILHEAD_TEST=1` adds `POST /__reset`, which puts the seed data back, for test runs.

It only takes changes (POST, PUT, PATCH, DELETE) from the pages it knows: the shop at `http://localhost:5173` or `http://localhost:4173`, and the Next.js app at `http://127.0.0.1:3005`. Anywhere else gets a 403, which is the cross-site check the React course's security lesson explains. If Vite picked another port, or you opened the shop at `127.0.0.1`, start the API with that address added, for example `TRAILHEAD_ORIGINS=http://localhost:5174 node trailhead-api/server.mjs`.
