Shopfront Ops

On-call runbook

The API is down

  1. Check it: bin/taskapictl status and bin/healthcheck.sh -r 3.
  2. Read the last errors: bin/taskapictl logs, or jq -r 'select(.level == "error") | [.ts, .route, .msg] | @tsv' logs/app.log | tail.
  3. Restart it: bin/taskapictl restart.
  4. Still failing after a deploy? Roll back: point releases/current at the previous release and restart.

Port 8080 is taken

ss -Htlnp 'sport = :8080'
fuser 8080/tcp

Stop whatever holds it, or start taskapi on another port by changing API_PORT and API_URL in .env.

The disk is filling up

df -h /
du -h --max-depth=1 . | sort -h

Old logs and backups are the usual suspects: bin/rotate-logs.sh and pruning backups/ free the most.

Restoring a backup

cd backups && sha256sum -c SHA256SUMS
tmp=$(mktemp -d) && tar -xzf backups/shopfront-YYYYMMDD-HHMMSS.tar.gz -C "$tmp"
diff -r "$tmp/config" config
